# Output Templates

cmobank-cmo は、依頼の種類に応じて以下のテンプレートを使います。

## CMO 提案書

```text
# CMO 提案書

## 1. 結論
我々は、〔狙う需要〕で No.1 を取りにいくべきです。

理由は、〔需要の青さ〕があり、かつ〔自社コア〕によって〔選ばれる理由〕を作れるからです。

## 2. 現在地
今この事業は、〔どの需要〕に、〔どんな供給〕を当て、〔どんなコミュニケーション〕で取引を成立させています。

改善余地は、〔需要 / 供給 / コミュニケーション〕にあります。

## 3. ビジネスゴール
- ゴール: 〔目標〕
- 期間: 〔期間〕
- 制約: 〔制約〕
- 成功条件: 〔成功条件〕

## 4. コアコンピタンス仮説
この事業のコアコンピタンス仮説は、〔構造的な強み〕です。

根拠:
- 〔成果 / 実績〕
- 〔顧客の声 / 継続理由〕
- 〔競合が真似しにくい理由〕

## 5. 青い需要候補
| 候補 | 需要の言葉 | 競合 | 人数 | 購入意欲額 | No.1 可能性 | コア適合 | 将来性 | 評価 |
|---|---|---|---|---|---|---|---|---|
| A | 〔需要〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔総評〕 |
| B | 〔需要〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔評価〕 | 〔総評〕 |

## 6. 狙う需要
狙う需要は、〔需要〕です。

この需要を選ぶ理由:
- 〔需要が強い理由〕
- 〔市場として十分な理由〕
- 〔自社が No.1 を取れる理由〕
- 〔未来も戦える理由〕

選ばない需要:
- 〔候補〕: 〔選ばない理由〕

## 7. 商品コンセプト
商品コンセプト:
〔誰に・どんな価値を提供する商品か〕

5 条件:
- 払ってでも欲しい: 〔評価〕
- 新しさ / 意外性: 〔評価〕
- ベネフィット: 〔評価〕
- 信じられる理由: 〔評価〕
- シンプル: 〔評価〕

## 8. USP / オファー
USP:
〔独自の強み + ベネフィット + オファー〕

オファー:
- お得感: 〔内容〕
- 低リスク: 〔内容〕
- 今やる理由: 〔内容〕
- わかりやすさ: 〔内容〕

## 9. コミュニケーション設計
MOA:
〔行動する瞬間の脳内情報空間〕

LP / セールス構成:
- FV: 〔入口〕
- 共感: 〔欲求・痛み〕
- 教育: 〔選ぶモノサシ〕
- 約束: 〔ベネフィット + 特徴 / 効果 / 証拠〕
- 交渉: 〔オファーへの YES〕
- 提示: 〔理想のシーン〕

## 10. ファネル
リーチ → 見込み客獲得 → CRM:
〔媒体・接点・数値仮説〕

## 11. センターピン
センターピンは、〔一点〕です。

理由:
〔ここが倒れると全体がどう連鎖するか〕

## 12. 重要仮説と検証
重要仮説:
〔この事業の成否を決める根本仮説〕

最小検証:
- 方法: 〔検証手段〕
- 期間: 〔期間〕
- 成功条件: 〔条件〕
- 失敗条件: 〔条件〕

## 13. 撤退・変更条件
- 継続: 〔条件〕
- 変更: 〔条件〕
- 撤退: 〔条件〕

## 14. 社長向け提案文
社長、〔狙う需要〕は大きく青く、我々の〔コアコンピタンス〕を使えば選ばれる理由があります。だから、ここで No.1 を取りにいくべきです。まずは〔センターピン〕へ集中し、〔重要仮説〕を最速で検証しましょう。
```

## 需要評価表

```text
| 需要候補 | 需要の定義 | 欲求 | 痛み | 競合 | 人数 | 購入意欲額 | No.1 可能性 | コア適合 | 将来性 | 判定 |
|---|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |  |
```

判定コメントには、必ず「なぜその評価か」を書きます。

## 商品コンセプト添削

```text
## 現在のコンセプト
〔原文〕

## 診断
- 狙う需要: 〔明確 / 不明確〕
- 誰に: 〔明確 / 不明確〕
- どんな価値: 〔明確 / 不明確〕
- ベネフィット: 〔ある / ない〕
- 信じる理由: 〔ある / ない〕
- シンプルさ: 〔評価〕

## 問題
〔最大の問題を 1〜3 個〕

## 改善案
〔改善した商品コンセプト〕

## USP 化
〔独自の強み + ベネフィット + オファー〕
```

```text
この LP が目指す MOA は、〔行動の瞬間の脳内情報空間〕です。

## 5 大要素レビュー
| 要素 | 役割 | 現状 | 問題 | 改善案 |
|---|---|---|---|---|
| FV | 触手を捕まえる |  |  |  |
| 共感 | 欲求・痛み |  |  |  |
| 教育 | モノサシ |  |  |  |
| 約束 | 商品説明 |  |  |  |
| 交渉 | オファー |  |  |  |
| 提示 | 理想 |  |  |  |

## 最大の詰まり
〔どこで MOA から遠ざかっているか〕

## 改善優先順位
1. 〔最優先〕
2. 〔次点〕
3. 〔余力があれば〕
```

## 検証計画

```text
## 重要仮説
〔この事業の成否を決める根本仮説〕

## 検証すべき理由
〔この仮説が崩れると、何が崩れるか〕

## 最小検証
- 方法: 〔広告 / LP / インタビュー / 体験会 / 手動販売〕
- 対象: 〔誰ではなく、どの需要を持つ人か〕
- 期間: 〔期間〕
- 必要サンプル: 〔数〕
- 成功条件: 〔条件〕
- 失敗条件: 〔条件〕

## 否定兆候
〔仮説が間違っていそうな兆候〕

## 次の判断
- 成功時: 〔進めること〕
- 失敗時: 〔変える / やめること〕
```
