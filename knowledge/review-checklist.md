# Review Checklist

提案・成果物を出力する直前に、cmobank-cmo 自身が回す最終監査です。すべて Yes / No で機械的に判定します。No が出た項目は、`knowledge/anti-patterns.md` の修正方法と `knowledge/quality-gates.md` の差し戻し先に従って直してから出力します。

軽微な添削依頼など出力が小さい場合も、関係するセクションだけは必ず回します。

## A. 需要(上流)

- [ ] 狙う需要を一文で言えるか
- [ ] 需要は人・属性・媒体・提供形態ではなく、欲しさ・痛み・実現したい状態で書かれているか
- [ ] 「30代女性向け」「初心者向け」「サブスク」のような切り方が、需要の言葉に翻訳されずに残っていないか
- [ ] 青い需要 3 条件(競合・人数・購入意欲額)を、仮説と根拠つきで評価したか
- [ ] 4 つのゲートを、合格条件(観測・計算)つきで通したか。希望的観測で通していないか
- [ ] 狙う需要は 1 つに絞られているか。複数需要を同時に狙う提案になっていないか
- [ ] 「なぜここで No.1 を取れるのか」が理由とセットで書かれているか
- [ ] 強みから需要を後付けしていないか(コアに旗は立てるが、確認は需要側で行ったか)

## B. リサーチ・ペルソナ

- [ ] 鳥の目・虫の目・魚の目の 3 視点が反映されているか。どれかが完全に欠けていないか
- [ ] ペルソナの痛み・願望は「シーン + 感情」で書かれているか。抽象語(快適・便利・安心)のままになっていないか
- [ ] 書いた需要・痛みは、本人固有の言葉まで降りているか。「誰でも書ける一般論」で止まっていないか
- [ ] n=1 由来の洞察に「未検証」のラベルがついているか

## C. 商品・コンセプト

- [ ] ベネフィット(感情)と効果(客観的変化)を混同していないか。「◯◯できる」で止まっていないか
- [ ] ベネフィットに、それを信じさせる証拠が直結しているか。証拠がベネフィットと無関係に立派なだけになっていないか
- [ ] ベネフィットは 1.5 メートル(現実的で実現可能な半歩先)に収まっているか。遠すぎ(人生が変わる)も近すぎ(少し楽になる)もしていないか
- [ ] コンセプトは一点に絞れているか。全部入りになっていないか
- [ ] コンセプト(内向きの思考ツール)とキャッチコピー・USP(外向きの表現)を混同していないか

## D. セールス・コミュニケーション

- [ ] セールスの 4 点セット(ベネフィット・正しい痛み・No.1 の理由・厚いオファー)が揃っているか
- [ ] 当てている痛みは「実在し、かつ自社が解決できる」痛みか
- [ ] オファーは「何を・いくらで・どうすれば」まで具体か。「お問い合わせください」に隠れていないか
- [ ] 3 つの Not(読まない・信じない・行動しない)すべてに対策があるか
- [ ] 教育(モノサシを渡す)と約束(商品説明)が分離しているか。モノサシを渡す前に商品説明を始めていないか
- [ ] LP / コピーが商品説明ではなく、MOA への書き換えとして設計されているか
- [ ] 媒体選定が上流(狙う需要・コンセプト)より先に来ていないか

## E. 提案の規律

- [ ] 事実・推定・仮説がラベルで分かれているか。出典のない数字を事実のように書いていないか
- [ ] SWOT・3C・財務整理で終わらず、需要・供給・コミュニケーションの言葉に変換されているか
- [ ] 結論が「この方向性もあり得る」ではなく、仮説と根拠を持った確信の構図で書かれているか
- [ ] 同時に、その確信が市場で検証すべき暫定解として扱われているか
- [ ] 重要仮説・最小検証(成功条件・失敗条件)・撤退/変更条件が含まれているか
- [ ] 検証が追認設計になっていないか。「この仮説が間違っているとしたら、どんな兆候が出るか」が書かれているか
- [ ] センターピン(オーバーリソースを投下する一点)が特定されているか

## F. 形だけの完成を疑う(最後に必ず)

- [ ] テンプレートの空欄を埋めただけになっていないか。枠が埋まっていても、リサーチが薄ければ未完成
- [ ] この提案を読んだ事業責任者は、明日何をすべきか分かるか
- [ ] 「これでいい」と思った箇所こそ、一度壊しにかかったか(確証バイアスの点検)
