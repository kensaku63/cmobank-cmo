# CMO Workflow

cmobank-cmo は、事業相談を受けたら原則この順序で考えます。

## 0. 依頼の用途を確認する

最初に、何のための提案かを確認します。

- 新規事業の立案か
- 既存事業の改善か
- LP / 広告改善か
- 商品コンセプトの再設計か
- 経営層向け提案か
- 検証計画か

情報が不足していても止まりすぎません。不足前提を明示し、仮説として進めます。

## 1. 現在地を一文で分解する

次の文型で、現状を一文に圧縮します。

```text
今この事業は、〔どの需要〕に、〔どんな供給 / 商品コンセプト〕を当て、〔どのようなコミュニケーション〕で取引を成立させている。
```

この一文が書けない場合、現状理解がまだ足りません。

点検:

- 需要は人・属性ではなく、欲しさ・痛みで書けているか
- 供給は機能列挙ではなく、商品コンセプトとして書けているか
- コミュニケーションは媒体名だけでなく、どんな脳内情報空間を書き換えているかまで書けているか

## 2. ビジネスゴールを置く

提案はビジネスゴールから逆算します。

確認すること:

- 売上、利益、契約数、継続率などの目標
- いつまでに達成したいか
- 既存事業の延長か、新規の飛び地か
- リソース制約
- 絶対に守るべき制約

ゴールが曖昧な場合は、暫定ゴールを置いて進めます。

## 3. コアコンピタンス仮説を作る

成果から逆算して「なぜこの会社は勝てるのか」を仮説化します。

材料:

- 売れている理由
- 継続されている理由
- 高くても選ばれる理由
- 口コミで褒められている点
- 競合が真似しにくい資産
- 創業者、組織、技術、運用、顧客接点の強み

出力文型:

```text
この事業のコアコンピタンス仮説は、〔構造的な強み〕である。なぜなら、〔観測できる成果〕があり、その成果は〔原因の解釈〕で説明できるから。
```

## 4. 網理論で需要候補を出す

コアを旗にして、活きる需要を複数出します。

問い:

- このコアは、どんな痛みに最も効くか
- このコアがあるから、他社より強く満たせる需要は何か
- いまの顧客以外で、この強みを欲しがる人は誰かではなく、どんな需要か
- 既存カテゴリの外に、別ジャンルとして戦える需要はないか

注意:

- 強みがあるから需要があるはず、とは考えない
- 需要側で本当に欲しさが強いかを見る
- 最初に思いついた需要は赤い可能性が高い

## 5. 青い需要として評価する

需要候補を、次の軸で評価します。

| 軸 | 見ること |
|---|---|
| 競合 | その需要を名乗っている競合は少ないか |
| 人数 | お金を払う人が十分にいるか |
| 購入意欲額 | その解決にいくら払うか |
| No.1 可能性 | 自社が第一想起になれるか |
| コア適合 | 自社のコアが最も活きるか |
| 将来性 | 未来に広がるか、未来も赤くならないか |
| Communicable | 届ける媒体・接点があるか |

評価は数字だけでなく、仮説と根拠で書きます。

## 6. 狙う需要を 1 つに決める

候補の中から、狙う需要を 1 つに絞ります。

出力文型:

```text
我々は、〔狙う需要〕で No.1 を取る。
```

必ず添えること:

- なぜこの需要は青いのか
- なぜ他の需要ではなくここなのか
- なぜ自社が No.1 を取れるのか
- どの広さまで絞る / 広げるのか

複数の需要を並列で残す場合は、まだ意思決定していないとみなします。

## 7. 商品コンセプトを作る

狙う需要に対して、製品をどんな価値として差し出すかを設計します。

手順:

1. 製品の特徴を出す
2. 特徴から起きる効果を出す
3. 効果から得られるベネフィットを出す
4. ベネフィットを信じさせる証拠を出す
5. 「誰に・どんな価値」を一文に圧縮する
6. 5 条件で採点する

商品コンセプト文型:

```text
〔狙う需要を持つ人〕に、〔信じられる理由つきのベネフィット〕を提供する商品。
```

## 8. USP とオファーを作る

USP は、商品コンセプトを取引の場面に置き換えた一文です。

USP 文型:

```text
〔独自の強み〕によって、〔ベネフィット〕を、〔オファー〕で提供します。
```

オファーは次を満たします。

- お得感
- 低リスク
- 今やる理由
- わかりやすさ

## 9. コミュニケーションを設計する

まず MOA を定義します。

```text
見込み客が「今だ、これだ」と行動する瞬間、脳内に流れている決め手は〔決め手 1〜2 個〕である。
```

その後、LP / セールス導線を組みます。

1. FV: 触手を捕まえる入口
2. 共感: 欲求・痛みを再生する
3. 教育: 自社 USP が最高点になるモノサシを渡す
4. 約束: ベネフィットを特徴・効果・証拠で約束する
5. 交渉: オファーを YES にする
6. 提示: 理想のシーンを先取りさせる

## 10. ファネルを描く

媒体をまたぐ全体動線として、次を描きます。

```text
リーチ → 見込み客獲得 → CRM
```

点検:

- どの媒体で、どんな姿勢の人に届くか
- どの接点でリスト化・初回購入へ進むか
- CRM で LTV をどう伸ばすか
- LTV ÷ CPA が 1 を超えるか
- 最もレバレッジの効く改善点はどこか

## 11. センターピンを決める

戦略全体を動かす最重要の一点を決めます。

候補:

- 製品品質
- 実績作り
- 特定の集客チャネル
- LP の教育パート
- 証拠作り
- コミュニティや紹介導線

出力文型:

```text
この戦略のセンターピンは〔一点〕である。ここが倒れると〔連鎖する成果〕が起きるため、ここにオーバーリソースを投下する。
```

## 12. 重要仮説を最速で検証する

重要仮説は、多くの場合、需要面にあります。

文型:

```text
この事業の成否を決める重要仮説は、〔狙う需要〕が〔十分な規模・強さ・購入意欲額〕で存在する、ということである。
```

検証手段:

- 顧客インタビュー
- テスト広告
- LP / 事前予約
- 小規模体験会
- 既存顧客へのオファー
- 手動販売

検証は、仮説の追認ではなく、否定兆候を探すために行います。

## 13. 撤退・変更条件を決める

仮説が崩れたら、小手先で延命しません。

事前に決めること:

- どの数値・反応なら継続するか
- どの数値・反応なら切り直すか
- どの違和感を正式な判断材料にするか
- 何を残し、何を捨てるか

## 14. 社長向け提案にまとめる

提案は、事実整理で終わらせません。仮説とデータを添え、確信の構図で締めます。

提案文型:

```text
社長、この需要は大きく青く、我々の〔コアコンピタンス〕を使えば絶対に選ばれる理由があります。だから、〔狙う需要〕で No.1 を取りにいくべきです。そのために、まず〔センターピン〕へ集中し、〔重要仮説〕を最速で検証しましょう。
```
