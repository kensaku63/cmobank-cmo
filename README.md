# cmobank-cmo

CMOBANK のマーケティングノウハウを使い、事業の上流戦略を設計する CMO 参謀エージェントです。

この agent は、事業を「需要・供給・コミュニケーション」に分解し、どの需要で No.1 を取るか、そこへどう至るかを仮説として提案します。資料要約ではなく、経営判断に使える狙う需要、商品コンセプト、ファネル、検証計画まで落とすことを目的にします。

## できること

- 現状事業を需要・供給・コミュニケーションの一文に分解する
- コアコンピタンスから青い需要候補を広げ、狙う需要を 1 つに絞る
- 商品コンセプト、USP、オファー、LP / ファネル案を設計する
- センターピン、重要仮説、最小検証、撤退・変更条件を提案する
- 社長・事業責任者に向けた CMO 提案書を作る

## 向いている依頼

- 「この事業のマーケ戦略を考えて」
- 「どの市場・需要で戦うべきか整理して」
- 「商品コンセプトと USP を作って」
- 「LP やファネルの構成を上流から設計して」
- 「新規事業の重要仮説と検証計画を出して」

## 使い方

```bash
aachat agent clone owner/cmobank-cmo --name cmobank-cmo
```

clone 後、project に参加させてから session を起動します。

```bash
aachat project assign <project> --agent cmobank-cmo
aachat session run cmobank-cmo --project <project> "この事業の CMO 提案を作ってください"
```

依頼時は、分かる範囲で以下を渡すと精度が上がります。

- 事業概要
- ビジネスゴール
- 既存商品・サービス
- 顧客・利用者
- 売上、継続率、口コミ、強みなどの実績
- 競合
- 現在の集客・販売方法
- 困っていること

## 主な出力

```text
1. 現状の一文分解
2. コアコンピタンス仮説
3. 青い需要候補
4. 狙う需要
5. No.1 を取れる理由
6. 商品コンセプト
7. USP / オファー
8. LP / コミュニケーションファネル
9. センターピン
10. 重要仮説と検証計画
11. 撤退・変更条件
12. 社長向け提案文
```

## 構成

- `identity.md`: エージェントの人格・役割・判断基準の正本
- `environment.yaml`: 必要な実行環境
- `knowledge/`: CMOBANK マーケティング原則、CMO ワークフロー、出力テンプレート
- `cmobank-book/`: CMOBANK マーケティングノウハウ本。`knowledge/` より深い章単位の背景理解・用語定義・思考プロセスの参照先
- `memory/`: session 間で引き継ぐ状態
- `.agents/skills/`: 実行時に使う専用 skill

## 知識の読み方

この agent は、依頼対応時にまず `knowledge/` を必ず読みます。`cmobank-book/` は、`knowledge/` だけでは判断が浅くなるとき、用語の厳密な定義や章単位の背景を確認するために参照します。

## 注意

secret、token、JWT、PAT、秘密鍵は repo に含めません。

この agent の提案はすべて暫定仮説です。最終判断は、市場テスト・顧客インタビュー・実データで検証してください。
