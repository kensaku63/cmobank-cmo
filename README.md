# cmobank-cmo

CMOBANK のマーケティングノウハウを使い、事業の上流戦略を設計する CMO 参謀エージェントです。

この agent は、事業を「需要・供給・コミュニケーション」に分解し、どの需要で No.1 を取るか、そこへどう至るかを仮説として提案します。資料要約ではなく、経営判断に使える狙う需要、商品コンセプト、ファネル、検証計画まで落とすことを目的にします。

## できること

- 現状事業を需要・供給・コミュニケーションの一文に分解する
- 鳥の目・虫の目・魚の目でリサーチし、ペルソナ脳内マップで生の痛みに憑依する
- コアコンピタンスから青い需要候補を広げ、4 つのゲートで判定して狙う需要を 1 つに絞る
- 商品コンセプト、USP、オファー、セールス(4 点セット + クロージング)、LP / ファネル案を設計する
- センターピン、重要仮説、最小検証、撤退・変更条件を提案する
- 社長・事業責任者に向けた CMO 提案書を作る
- 事業ごとの確定事項・検証結果を `memory/` に蓄積し、session をまたいで仮説検証ループを回す

## 向いている依頼

- 「この事業のマーケ戦略を考えて」
- 「どの市場・需要で戦うべきか整理して」
- 「商品コンセプトと USP を作って」
- 「LP やファネルの構成を上流から設計して」
- 「新規事業の重要仮説と検証計画を出して」

## 使い方

```bash
aachat agent clone owner/cmobank-cmo --name cmobank-cmo
```

clone 後、project に参加させてから session を起動します。

```bash
aachat project assign <project> --agent cmobank-cmo
aachat session run cmobank-cmo --project <project> "この事業の CMO 提案を作ってください"
```

依頼時は、分かる範囲で以下を渡すと精度が上がります。

- 事業概要
- ビジネスゴール
- 既存商品・サービス
- 顧客・利用者
- 売上、継続率、口コミ、強みなどの実績
- 競合
- 現在の集客・販売方法
- 困っていること

## 構成

- `identity.md`: 役割と CMOBANK 思想の核(数行)。普段はこれだけで動く
- `.agents/skills/`: 業務ごとに CMOBANK の考え方を注入する skill。リサーチ・需要選定・コンセプト・セールス・LP・検証・全体提案・正本文書づくり(一覧は `.agents/skills/README.md`)
- `memory/`: session 間で引き継ぐ事業ステート(形式は `memory/README.md`)
- `cmobank-book/`: skill の蒸留元になった CMOBANK ノウハウ本の原典。実行時には参照しない
- `environment.yaml`: 実行環境

## 設計方針

CMOBANK の考え方は、思考の邪魔にならない軽い方向付けとして使う。identity には核だけを置き、業務に入ったときだけ該当 skill でその業務のエッセンスを足す。skill にもフレームワークの全文やチェックリストは載せず、判断を変える考え方だけを書く。

## 注意

secret、token、JWT、PAT、秘密鍵は repo に含めません。

この agent の提案はすべて暫定仮説です。最終判断は、市場テスト・顧客インタビュー・実データで検証してください。
