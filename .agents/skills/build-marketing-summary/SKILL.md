# Build Marketing Summary

マーケティングサマリーを一冊の説明資料ではなく、権威レベルを分けた文書システムとして作る。情報量ではなく、制作判断への影響度で内容を選ぶ。

## 最初に行うこと

1. 対象事業の既存文書、確定事項、未検証仮説、リサーチを読む。
2. 目的、利用者、利用場面、完成条件を確認する。
3. 本文を書く前に、文書体系と権威レベルを提案して人間と確定する。
4. `references/document-architecture.md` を読み、既存構成へ無理なく適用する。
5. 上流の内容を決めるときは `$AA_AGENT_DIR/knowledge/` のCMO正本と該当リサーチ手順を読む。

情報が不足していても、確定事項と仮説を分けて提案は進める。ただし、未検証仮説を確定したCanonへ昇格させない。

## 4段階の権威レベル

必ず次を分離する。

1. **Verbatim Canon** — 一言一句を正とする公式文言。
2. **Decision Canon** — 文言ではなく意味とマーケティング判断を正とする。
3. **Reference** — 正本を理解・応用するための根拠、生の声、例、詳細情報。
4. **Workbench** — 候補、比較、反対意見、未確定仮説、壁打ち過程。

Verbatim Canonは「どう言うか」の正本、Decision Canonは「何を意味するか」の正本とする。ReferenceとWorkbenchを公式見解として引用しない。

## 作成ワークフロー

### 1. 目的と編集原則を決める

少なくとも次を一文で答えられるようにする。

- 誰が、いつ使うか。
- この文書群によって、どの判断を揃えるか。
- 何を載せないか。
- どうなれば完成か。

### 2. 文書体系を決める

内容の壁打ちより先に、各文書の役割、権威レベル、優先順位、更新ルールを確定する。既存の文書管理契約がある場合は、それを優先して構造を適合させる。

### 3. Workbenchで一論点ずつ壁打ちする

狙う需要、提供価値、選ばれる理由、約束、事業定義、ブランドメッセージの順を基本とする。下流のコピーから始めない。

各論点で明示する。

- 決める問い
- 事実
- 推定
- 仮説
- 候補
- 推奨と理由
- 棄却理由
- 未検証事項
- 確定時に更新するCanon

### 4. 判断を昇格する

人間が確定したら、検討過程をCanonへコピーしない。

1. 決定理由をDecision Logへ残す。
2. 現在の意味と判断だけをDecision Canonへ反映する。
3. そのまま使う必要がある文言だけをVerbatim Canonへ圧縮する。
4. 根拠、用例、生の声はReferenceへ置く。

### 5. 制作利用を検証する

サービスサイト、SNS、動画など異なる媒体を想定し、次を確認する。

- 制作者が、狙う需要と最重要価値を迷わず判断できる。
- 媒体に合わせて表現を変えても、Decision Canonの意味が変わらない。
- Verbatim Canonの文言が無断で言い換えられない。
- 主要な約束に証拠が接続されている。
- 誤ったカテゴリー認識や禁止表現を排除できる。
- Referenceの例が公式コピーと誤認されない。

### 6. 正本を保守する

- Canonには現在の結論だけを置く。
- 過去の経緯はDecision Logへ移す。
- 同じ判断を複数のCanonに重複記載しない。主たる正本を一つ決め、他は参照する。
- 仮説が市場で否定されたら、コピーだけでなく需要・価値・選ばれる理由まで戻る。
- 変更時は影響するCanon、Reference、チェックリストを同時に点検する。

## 品質基準

- 狙う需要、最重要価値、選ぶモノサシ、中心メッセージを一つに絞る。
- 正しい情報でも制作判断を変えないならCanonへ載せない。
- Verbatim Canonに背景説明、候補案、例を入れない。
- Decision Canonに調査ログを入れない。
- Referenceでは事実、推定、仮説、出典、確認日を区別する。
- Workbenchには「正本として使用しない」と明記する。
- 抽象的な形容詞ではなく、制作物をYes/Noで判定できる原則を書く。
- 公開前に制作チェックリストでセルフ監査する。

## 完了条件

- 各文書の権威レベルと使用ルールが明記されている。
- 文書間の優先順位と矛盾時の扱いが決まっている。
- WorkbenchからCanonへの昇格経路がある。
- Verbatim CanonとDecision Canonの役割が混ざっていない。
- 制作者が追加説明なしに制作・レビューできる。
- 未確定仮説が確定事項として混入していない。
- プロジェクト固有の判断はプロジェクト文書にあり、このskillへ混入していない。
