# Hypothesis Test

戦略は暫定解。最も根本の前提を、最も速く安く確かめる。

## 考え方

- センターピン: それを倒せば全体が連鎖して動く一点。そこにリソースを集中させる
- 重要仮説: 「これが成り立つから事業がうまくいく」根本の前提。たいてい需要側にある(その需要は実在するか、痛みは十分強いか、その額を払うか、約束を信じるか)
- コピーや価格の細部より先に、根本の需要仮説を検証する
- 検証は追認ではなく反証探し。「間違っているなら、どんな兆候が出るか」を先に書く
- 手段は速い順に選ぶ: 生の声の調査、インタビュー、テスト広告、LP / 事前予約、手売り、小規模体験会、コンシェルジュ型 MVP
- 成功・失敗・判断保留の条件は実施前に決める
- 根本が崩れたら、価格やコピーの手直しで延命しない。大きく変えるか、やめる。「ここまでやったから」は続ける理由にならない

## 出力

- センターピン(倒れると何が連鎖するか)
- 重要仮説と、それが崩れたら何が崩れるか
- 最小検証: 方法・対象・期間・サンプル・成功 / 失敗 / 保留の条件
- 否定兆候
- 次の判断: 成功なら / 失敗なら / 保留なら

継続中の事業なら、仮説と結果を `memory/<事業>.md` に残す。
